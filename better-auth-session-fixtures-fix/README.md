# Better Auth required session field, patched control

This is the fixed control for [the unpatched reproduction](../better-auth-session-fixtures/).
Both directories use the same verifier, Node 24.19.0, pnpm 11.15.1, and published
`better-auth@1.7.3`. The only behavior change is a committed pnpm patch.

## Run

From this directory after cloning the `repro/better-auth-session-fixtures` branch:

```sh
pnpm install --frozen-lockfile && pnpm verify
```

Expected output, exit code **0**:

```text
EXPECTED: login accepts providerToken and returns an authenticated session.
ACTUAL: login and authenticated lookup preserve providerToken=fixture-token.
```

The verifier asserts the supplied field on both the newly created session and a
subsequent lookup using the returned cookie header. Any mismatch exits nonzero.
It closes the in-memory SQLite database and needs no server or real credentials.

## Patch provenance

`patches/better-auth@1.7.3.patch` adds optional `session` input to the three test
auth helpers. It supplies custom fields before session persistence and keeps
standard session fields generated by Better Auth. Explicit custom values can
override defaults. No production endpoint is added.

The runtime patch is copied from the built `auth-helpers.mjs` of the upstream
change based on `better-auth/better-auth` commit `cfedf97db`. Declaration changes
mirror its `TestAuthOptions` input and exports. The patch changes only this plugin;
no local workspace dependencies or unrelated upstream changes are included.

See `verification.txt` for clean-checkout proof. The baseline exits 1 with the
required-field constraint error; this control exits 0. Local Node is required for
`node:sqlite`; no StackBlitz or deployed runtime result is claimed.
