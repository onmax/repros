# Nuxt 5 build: core plugin hooks that run JS for every module

> Written by an AI agent (Claude Code); not yet reviewed by a human.

## Problem

In a Nuxt 5 production build several core Vite/Rolldown plugin hooks have no native `filter`, so the bundler calls
into JavaScript for (nearly) every module even though each hook can only act on a few ids. `nuxt:vue-packages` also
re-resolves the same Vue specifiers once per importer. Each unfiltered `transform` hook costs measurable build time.

## Environment

- `nuxt-nightly@5.0.0-2611142141-73d92c4` (Nuxt main `73d92c47c`), Vite 8.3.8, Rolldown 1.3.2, Nitro 3.0.261103-rc
- Node.js 24.22.1, Linux
- The app is generated by `generate-app.ts`, a copy of Nuxt's `test/bench/large-app.ts` (the bench `large`
  fixture: ~170 pages, ~370 components, plugins, middleware, server routes and a layer).
- `modules/count-hooks.ts` counts JS calls per plugin hook; `modules/noop-hooks.ts` adds N no-op unfiltered hooks.

## Verify

```sh
git clone --branch repro/nuxt-build-hook-overhead https://github.com/onmax/repros.git
cd repros/nuxt-build-hook-overhead
npm run verify
```

Expected: each listed hook is called a handful of times. Actual (exit 1 if not reproduced):

```text
REPRODUCED   1292  nuxt:runtime-paths-dep transform  (acts only on modules containing __VITE_ASSET__)
...
=> one unfiltered transform hook costs about 106 ms per build of this app
```

The full output of a verified run is in `verify-output.txt`.

## Why each part is here

- The generated app: the counts scale with module count, so a minimal app hides the cost.
- `noop-hooks.ts`: prices one unfiltered hook in this app without touching Nuxt.
- Wall time is noisy on a busy machine; the counts are deterministic, the price is a min over alternating runs.
