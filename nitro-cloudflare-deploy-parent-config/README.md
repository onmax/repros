# Nitro: `nitro deploy` fails for a Cloudflare app below another Wrangler config

The `cloudflare_module` preset saves the deploy command `npx wrangler --cwd ./ deploy`. It works only through Wrangler's [generated configuration redirect](https://developers.cloudflare.com/workers/wrangler/configuration/#generated-wrangler-configuration) in `<app>/.wrangler/deploy/config.json`. Wrangler applies that redirect only when it sits next to the user's Wrangler config file. In a monorepo where the app has no Wrangler file of its own but the repository root has one (for another Worker), Wrangler finds the root file first and stops:

```
A deploy configuration file is generated by a build tool to redirect Wrangler to the configuration it generated.
It is only applied when it sits alongside the user configuration file, which here would be "../../../.wrangler/deploy/config.json".
```

Pinned: `nitro@3.0.261103-rc`, `rolldown@1.3.2`, `wrangler@4.163.0`, Node 24.

```sh
cd apps/web
npm install
npm run verify
```

Expected: `nitro deploy --prebuilt . -- --dry-run` deploys `.output/server/wrangler.json`.
Actual: Wrangler fails with the error above. `verify` exits 1.

The root `wrangler.json` and `another-worker.js` stand for another Worker in the same repository. Without them the deploy works.
The same command also fails when `.output` is deployed from another directory (for example a CI artifact), because the redirect stays in the app root: `Could not detect a directory containing static files`.
`npx wrangler deploy --config .output/server/wrangler.json` works in both cases.
